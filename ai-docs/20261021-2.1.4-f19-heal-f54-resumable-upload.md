## 1. F-19：为什么加密稿「丢回执」会多弹一张面，怎么修的

**问题陈述**（输入 → 输出）：
- 输入：一篇加密稿，这台设备 `save()`；上传真落到了云端，但回执没回来（iOS 锁屏杀掉在途请求、网络抖一下）；页面死了。
- 应该：下次开页 `pushAll` 重推 → If-Match 旧基准 → 412 → `tryHeal` 拉云端那份逐字节比 → **一样** → 认领、清 dirty，不打扰人。明文文件一直是这样。
- 实际（2.1.3 及以前）：**弹冲突面**「云端有新版本」，两边其实是同一篇。

**根因**：`save()` 封两次。先 `sealForWrite(plain)` 封一次落本机（密文 L），再把 **plain** 交给 `push()`，`doPush` 又 `sealForWrite` 一次（密文 C，随机 salt / IV 不同）推上云。云端是 C、本机是 L。回执丢了之后重推的是本机那份 L（`pushLocalBytes`），412 后 `tryHeal` 拿 L 比云端的 C → 不等 → 当真分叉 → 面。在途重试（同一次 save 里）不会出这个问题，因为重试复用的是 C；只有「页面死了、下次从本机重推」这条路会。

**修法**：`save()` 把**刚落本机的那份密文**交给 `push()`（`encode: () => sealed`）；`sealForWrite` 对已是容器的输入本来就原样透传（搬运路径），所以云端 == 本机逐字节。明文文件 `sealed === plain`，零变化。不用记明文哈希、不用解开再比——周账里那两条「根治」方案都不需要。

**替身也修了**：`src/testing/mock-encryption.ts` 以前封包是确定性的（同明文同字节），所以这个 bug 在 500 条测试里从没露过脸；现在每次封包带 8 字节随机 nonce，和真容器一样。回归测试 `test/enc-lost-response-heal.test.mjs`：① `save()` 推云字节 == 本机 at-rest 字节；② 注入丢回执 + `pushRetry.maxAttempts=1`（= 页面死了不在途重试）→ `pushAll` → `healed`、不弹面、dirty 清。旧码两条都红。

## 2. F-54：上传会话落盘

**问题**：Graph 分块上传（> 4 MB）的会话 URL 只在内存。WeebPaint 几十 MB 的画、KudsRocket 的快照，上传到一半刷新 / iOS 杀页 / 关机 → 下次整份从头传（W-23）。0.17.1 的单块续传只救同一次会话里的网络抖动。

**做法**：`createStore({ uploads: { resumable: true } })`（**默认关**）：
- 推 > 4 MB 的字节时，store 给 provider 一个「记忆面」（`UploadSessionPort`）：`token` = 这份字节的 sha256（**只认「是不是同一份字节」，不是文件身份**——身份永远是路径；家族否决的是内容哈希当身份）；记录住 store 的 kv `internal.upload-session:<名>`，值 = 会话 URL / 大小 / If-Match / token / 时间，**没有内容**。
- Graph 开会话时 `save`；下次推同一份字节（token、大小、If-Match 都对、没过期）先 `GET uploadUrl` 问 `nextExpectedRanges`，从那里接着传，**不重开会话**；会话没了（404 / 过期）→ 清记忆、重开；字节变了（token 不同）→ 重开。
- **续上的会话一律提交最后一块前核一次 eTag**（不看 `verifyChunkedCommit` 开关）：中间隔了多久不知道，云端可能被别的设备动过；变了 → 撤会话、清记忆、412 → 冲突面。
- 传完 / 412 / 4xx → 记忆清掉。只有「连续失败放弃」（网络）才把记忆留着——那正是要续的情况。
- ≤ 4 MB 走简单上传、没有会话，不记。`uploadStream`（KudsRocket 上传盘，字节来自 File 句柄）不记：iOS 的 File 句柄活不过一次会话，续不了。

**谁来触发续传**：不用新接口——`pushAll`（回线 / 回前台 / 登录后）、`drainUploadQueue`、再次 `save` 同一份字节，都走同一条 push，记忆面在里面自动认。app 要做的只有开关 + 它本来就有的续推时机。

**消费方**：WeebPaint（道 2 收 2.1.4 时开）、KudsRocket（W-23，快照 > 4 MB 的都受益）、WXHW / MoonSinger 文件小，开不开无感。

测试：`test/graph-upload-session-resume.test.ts`（第一轮断在第二块 → 记忆留着 → 第二轮只传剩下两块、不重开会话、核 eTag、传完清；token 不同重开；会话 404 清记忆重开；续上的会话提交前 eTag 变了 → 412 + 清）+ `test/store-upload-session.test.mjs`（开关 / 阈值 / token 稳定性 / 记忆面读写走 kv）。
