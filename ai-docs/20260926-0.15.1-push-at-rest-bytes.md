# 0.15.1 — 补推 / 离线回放直推本地 at-rest 字节（加密件推送不再要密码）
> created 20260926 · by Claude Fable 5.1 · as-of 0.15.1

## 起因（WXHW 真机，2026-09-26）
user 登出态新建书 → 加密 → reload → 登录：书一直「未上传」。链条之一在库：`files.dirty.pushAll()` / 离线上传回放共用的 `pushLocalBytes` 先 `seal.unsealForRead`（要内存密码）得明文，再交 `doPush` 让 `sealForWrite` 重新封——锁着（reload 后密码没了）= `status:"locked"` 算失败留 dirty，谁也推不动。user 原话：「为什么推加密件需要密码。不就是二进制吗」→「修法 = store 里两行：本地字节已是容器就直推，不解不封。修」。

## 改动
- `create-store.ts pushLocalBytes`：读本地字节 → **原样** `doPush(name, { encode: () => atRest })`。`sealForWrite` 本就对「已是容器」原样透传（搬运路径）、对明文文件原样（prev 非容器），所以走的还是同一条 vetted push（If-Match / N6 / 撞名 surface / B5 重试逐字节相等）。`"locked"` 状态从此路径消失。
- `dirty.pushAll` 文档：失败原因去掉「加密锁定」。
- 测试 `store-dispose-dirty.test.ts`：登出态 `save(tryPush:false)` → 有密码时 `encrypt()`（云腿 deferred）→ 密码置空 + 回线 → `pushAll` pushed=1、云端字节 = 本地容器逐位相同、账清。415 绿。

## 不变
公共面（api/*.d.ts）零变化；本地 at-rest 与云端 at-rest 仍是同一份字节；解密 / 换密码 / 首次加密照旧要密码（那些真的要碰明文）。
