# 2.1.2：`file.delete()` 改叫 `file.trash()`（词对准语义）；列举行带 `kind` / `tier`

## 1. `delete()` → `trash()`

库里「删除」从第一天起就是**移进回收站**（MASTER §A：删除 = 移到 .trash；本地 move-aside、云端 move-aside，可恢复）。动词叫 `delete` 一直在撒谎——读代码的人以为是销毁，于是有「把它摆在没同步好的行上当删本地」那类误用（0.18.3 的滥用警示）。为什么不是 `recycle`：那是 Windows 味，动词义是「回收再造」；`discard` 听着不可逆；`remove` 太泛。`trash` 是 macOS / Finder / Gmail 的动词，也正是我们 `.trash` 夹、库内 `trashMod` / `local.trash` / `cloud.trash` 用了两个月的词。

- `RawFile.trash(): Promise<TrashOutcome>`（`ZipFile` 同）。返回值类型 `DelResult` → **`TrashOutcome`**，字段和 `status` 串（`trashed` / `cancelled` / `noop` / `queuedCloudDelete`…）一个没动。
- **没有别名、没有过渡期**：钉旧版的消费方不受影响；升级时编译错误就是迁移清单（家族惯例）。
- 没改的：`files.deleteFolder()`（真删**空**夹，不是回收站，词是对的）；`CloudProvider.delete()`（provider 层的硬删原语，`purgeTrash` 用）；UI 文案键 `file.deleting`（用户看到的字仍是「删除」——那是界面语言，不是 API 语义）。
- 内部模块 `works/delete.ts` 文件名没改（里面的职责注释已经写着「删除 = move-aside」）。

**消费方升级清单**：`.delete()` → `.trash()`；`import type { DelResult }` → `TrashOutcome`。gallery 包（`@internal/gallery`）里的「删除」动词走 `file.delete()`——它收 store ≥ 2.1.2 时同改。各家的 red-line guard 若扫 `\.(save|delete|tryMove|reupload)\(`，加上 `trash`（skill 已改）。

## 2. 列举行带 `kind` / `tier`

`watchFolder` 吐的 `Item` 多两个字段：`kind?: string`（docKinds 表的 kind；不是本 app 文档的名字 → 没有这个字段）、`tier: DocTier`（不是文档 → `"work"`）。库用 docKinds 表填好，和 `syncState` 一样是**库给的事实**，下游不要再从名字重推一份。gallery 画「自动」「只读」徽章直接读。
