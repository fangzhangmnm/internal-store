# 2.2.6（patch）：`save` 自己守离线 + 列表条目带「云端那份是加密容器」

> created 20261104 by Claude Fable 5.1 · as-of 2.2.6 · user 2026-11-04「列表带加密可以」「库自己守同意」· 两件都是「库填事实、守红线，六家一次对齐」，不是新 API 形状

## 1. 改了什么（两处）

1. **`file.save()`**（`create-store.ts`）：`tryPush` 默认为真时，先看 `isOnline()`（= 宿主的 isOnline ∧ 已登录；宿主选了「离线继续」就是假）。假 → **一条网都不打**，直接回 `{ pushed: false, reason: "offline" }`；文件照旧落本地、留 dirty；ADR-0018「从没同步过的入补推队列」照旧。以前这里直接 `pushMod.push` → `fetchMeta` / `upload` 必失败才回 reason（MoonSinger 工单 H4 用 mock 请求日志抓到：`getItemByPath`、`upload` 两条）。
2. **`Item.cloudSealed?: true`**（`works/listing.ts`）：列举时 cloud-sync 给每条云端文件的 `path`（真实名）和 `name`（toName 后的身份）；两者不同 = 加密容器名（全库唯一的加密名判定 seam，含「身份本身以 .zip 结尾的 app 走 config.toName」的例外）→ 写 `cloudSealed: true`。明文 / 不知道（老 mock、stale 视图没给 path）不写这个键。**零多余请求**：列目录本来就拿到名字。不参与 syncState / badge。

## 2. 为什么

- 1：闸门设计稿（家族根 `ai-docs/20261103-cloud-gate-design.md`）「库离线一条网都不打」对 collection 2.2.4 守了、对 `file.save` 没守；app 侧补 = 六家各补一次（user 11-04：「store 就是为了安全行为对齐，为什么每个子项目都飘」）。
- 2：gallery 0.8.11 把卡片的加密态改成「本地字节 ∨ store 的事实」取或，但 store 的列表条目没带「云端那份是不是容器」→ 纯云端、这台没字节的加密件第一次打开前锁不亮、旧明文封面可能还显（CatsUp 11-03 报告 C2 / C3 追加）。事实归 store（家规「gallery 是前端、数据事实归 store」）。

## 3. 行为差异

| 场景 | 2.2.5 | 2.2.6 |
|---|---|---|
| 宿主 isOnline 为假时 `save()`（默认 tryPush） | 发 fetchMeta / upload，失败后 reason = error / 具体状态 | 不发请求，reason = `"offline"`；其余（本地落盘、dirty、补推队列）一样 |
| `save({ tryPush: false })` | 不变 | 不变 |
| 列举出的 Item | 没有加密事实 | 云端是容器的多一个 `cloudSealed: true` |

## 3½. 为什么第 1 条默认开、不走「默认关 + 消费方显式开」（本库规矩 ④）

- 它不是新行为，是把 2.2.4 已经对 collection 成立的契约「宿主说离线 = 库一条网都不打」补到 `file.save` 上；默认关 = 洞继续开着，等于没修。
- 对宿主可见的结果和以前完全一样：本地落盘、留 dirty、补推队列照入、`pushed:false`；只有 `reason` 从「请求失败后的状态」变成 `"offline"`，而宿主要么不看 reason、要么本来就按 `pushed` 判。
- 只在宿主**自己**把 `isOnline` 返假时生效（选了「离线继续」/ `navigator.onLine` 假 / 没登录）；在线路径一个字节没动。
- user 2026-11-04 原话「库自己守同意」= 这一条就是要库替六家一起守，开关交回宿主正是它要消灭的「每家各补一次」。
