# 2.2.3（patch）：「处理…」弹面之前先做回执丢失自愈

> created 20261103 by Claude Fable 5.1 · as-of 2.2.3 · user 2026-11-03「1 可以」（批准改库）· 家族周账 F-142
> 起因：MoonSinger 工单 A2 的 e2e「登录后补推：自愈…不弹冲突面」在 2.2.2 上红——云端字节 = 本机字节（sha256 相同），点「处理…」照样弹「云端和本机各有一版新改动」。

## 1. 改了什么（一处）

`create-store.ts` `file.resolve()`：算出 cloudState = `"changed"`（云端版本号 ≠ 本机基准）之后、弹面之前，先 `safeResolve.tryHeal(name, 本机 at-rest 字节)`——拉云端那份逐字节比，一样 = 上次推其实早落了云、只是回执没回来 → `markSynced`、不弹面、返 `{ status: "pushed" }`；不一样 / 拉不到 → 照旧弹面。

这不是新机制：push 路（412 → `tryHeal`）从 0.x 起、open 路从 2.2.2 起都这么做。缺口是**「处理…」这条路**：10-26 各 app 撤掉登录后的批量推（它会撞 412 走到 tryHeal）之后，「处理…」成了「要处理的」唯一入口，却没人比字节。

## 2. 行为差异（艺术类 app 升级逐条过）

| 场景 | 2.2.2 | 2.2.3 |
|---|---|---|
| 本机脏 ∧ 云端版本号变了 ∧ **云端字节 = 本机字节**（回执丢失） | 弹面「云端和本机各有一版新改动」（这句是假的） | 不弹面，直接认领：脏标清、基准 = 云端版本号，`resolve()` 返 `pushed`；再按 = `clean` |
| 本机脏 ∧ 云端版本号变了 ∧ 字节不同（真分叉） | 弹面 | 多拉一次云端字节再弹面（同一张面、同样三选一） |
| 本机脏 ∧ 云端没动（unchanged）/ 云端没了（absent / never） | 弹面 | 不变（不比字节） |
| 二等自动备份 | 不弹面、keepMine 推 | 先比字节：一样就不推了（省一次上传）；不一样照旧 keepMine 推 |

成本：真分叉时多一次下载（和 open 路的自愈一样大小）。不改任何 API、不加导出、不改面的三个选项。

## 3. 为什么默认开、不做开关（库政策 ④）

- 它不是「新行为」，是把同一条自愈规则补到漏掉的第三条路上；push 路和 open 路的同一条规则都是默认开的，只有这条路关着 = 三条路对同一状态给两种答案。
- 它只在**字节完全相同**时改状态（dirty → synced），一个字节都不会丢、不会盖；不相同时和 2.2.2 完全一样。
- 不修的代价是面上说假话（「各有一版新改动」而其实一样）——家规 10-26「UX 误导 = 数据安全缺陷」。做成默认关 = 默认留着假话。
