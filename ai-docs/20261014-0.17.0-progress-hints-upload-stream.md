## ① `save(bytes, {onProgress})` / `UploadOpts.onProgress`

Graph 简单上传（≤ 4 MB）报 0 和 total；分块上传每块报一次；folder / mock provider 同口径。只给宿主画进度条，不作任何决策。
起因：KudsRocket 的单个文件 10 MB、上行慢的网络上传几十秒，状态条只能转圈。

## ② `watchFolder` 完整云端帧 = 新鲜度证据（`src/fresh-hints.ts`）

本地有副本的 `open()` 原来每个都先 `fetchMeta` 一趟；打开文档时几十个小文件全在刚列的那一帧里，同一份 Graph 事实再问一遍。
安全边界：只在「帧里的 etag === 本 tab 已见 base」时采信（= 云端没动 → in-sync）；帧说动了 / 没有 / 本 tab 没 base 一律照常问云端；30 s 时效；只喂 complete 帧。
采信窗口内云端真动了 → 和 fetchMeta 之后再读本地的 TOCTOU 一样：下次 push If-Match base → 412 → 冲突面。红线 §A 每一行不动。

## ③ `files.uploadStream(identifier, source, {onProgress})`（`CloudProvider.uploadStream?` · `cloud-sync.pushStream`）

「边加密边上传、不留本地副本」：上 GB 的媒体文件，整份进内存 / IDB 都不行。宿主按 `source.read(offset, length)` 逐块给，Graph 上传会话逐块传（最后一块落地才成文件，中途断了云端没有半成品）。
只新建（`conflictBehavior:"fail"`）：身份已占（本地或云端）→ `CloudNameCollisionError`，一个字节不传；离线 / 未登录 → 抛（没有本地字节可排队）。
不经 seal（库加密不适用——宿主自己封好的容器才走这条）、不落本地、不写 etag / dirty；成功后 cloud-only，`open()` 走 acquire 建谱系。
provider 没实现 → 抛，绝不退回整份拼 Blob。folder provider：`createWritable` 逐块写、close 原子替换。busy 键 `file.uploading`（宿主可路由到后台提示）。

## ④ 顺手：`save()` 推完再发一帧

`notifyFolderOf(name)` 原来只在本地落地那一刻发（badge「没传上去」），推完不发 → 订阅者的计数停在旧帧（KudsRocket 10-14「说需要处理，重开又是对的」）。现在推完（成没成）再发一帧。
