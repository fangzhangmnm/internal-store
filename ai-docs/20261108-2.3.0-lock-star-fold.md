## 1. 加了什么

两个 `createStore` 开关，**都默认关；关着 = 2.2.7 的全部行为**（旧的 554 条测试一条没改、原样绿）。

1. **`lockByDefault: true`** —— 一等作品默认只读。没有活着的解锁，`file.save`（改已有的）抛 `LockedError`，在任何副作用之前（不标脏、不落盘、不打网）。
   - `files.unlock(identifier)` / `files.lock(identifier)` / `files.unlockOf(identifier)` / `files.watchUnlocks(cb)`；`files.lockByDefault` 给前端看开关。
   - 一枚解锁逐件、只记本机 kv（`internal.unlocks`）、不同步；放凉 `unlockTtlMs`（默认 24 h）过期，每次成功的 save 往后推；`activeIdentifier()` 指着的那份过期不打断。
   - `mode:"new"` 的首存不拦，存成后带一枚解锁；`save(…, { bornLocked: true })` = 生来锁着。
   - 改名 / 移动成功解锁跟着新身份走；进了回收站解锁不留。
2. **`fileMarks: true`** —— 星和收起，记在一份库自己的 collection（云端 `.${appId}/store.file-marks.json`）。
   - `files.star / unstar`：加了星的拒绝送进回收站——`file.trash()` 抛 `StarredError`；`resolve()` 的面里选「这份进回收站」→ `unresolved / starred`；云端没了过宽限机器也不自动送，停在 `pendingGone`。
   - `files.fold / unfold`：纯显示记号，库不藏东西、不拦动作。
   - 列举带 `Item.starred` / `Item.folded`（只在 true 时写）；记号变了那一夹自动重画；改名 / 移动成功记号跟着走。
3. 出口多了 `LockedError`、`StarredError`、类型 `Unlock`、`FileMarks`。新文件：`src/works/unlocks.ts`、`src/works/marks.ts`。

## 2. 为什么（服务哪条目标、碰哪几行威胁）

- 目标（`ai-docs/20261016-data-safety-model.md` §2）：第 1 条（云端已有的作品不被盖掉）和第 2 条的前一道——手滑改坏旧作品、手滑删掉要紧的作品，在走到同步之前就拦住。威胁行：§3 A12（误操作：误删、误改）、D6（家人 / 小孩 / 猫碰到开着的设备）。
- user 2026-11-08：「到时候演示所的设计得设计的非常的瑞士奶酪，非常的安全，甚至是我们在库这一层里面本身拒绝写入。」（演示所 = 演示锁，语音。）库是三层里的最后一层。
- 「自动只许拦，不许替人管」：这一版没有加任何后台自动的东西。唯一的定时器只为了在过期那一刻通知界面（问 `unlockOf` 永远是现算的）。

## 3. 行为差异

**开关都关着：没有。** 下面是打开之后。

| 场景 | 2.2.7 | 2.3.0 开了 `lockByDefault` |
|---|---|---|
| 对一份已有的一等文档 `save`，没解锁 | 存 | 抛 `LockedError`，一个字节不动 |
| 自动保存（`tryPush:false`）撞上过期 | 存 | 同上——所以 app 的自动保存、崩溃影子只在解锁期间工作，要先改好再开开关 |
| `mode:"new"` 新建 | 存 | 存，并带一枚解锁（除非 `bornLocked`） |
| 存下没传的字节，之后锁上 / 过期 | — | 照样补推（`dirty.pushAll`、离线补推、`resolve()`、`reupload` 都不拦） |
| 云端有新版、这台干净 | 快进 | 快进（锁不拦同步） |

| 场景 | 2.2.7 | 2.3.0 开了 `fileMarks` |
|---|---|---|
| 开夹 | 一次列举 | 多一次记号文件的 `fetchMeta`（云端没变就到此为止）；第一次用时多建一份云端文件 |
| `trash()` 加了星的 | — | 抛 `StarredError` |
| 云端没了、过了 24 h 宽限、加了星 | 本机那份自动进回收站 | 不动，停在「要你处理」 |
| 记号读不出来（本机库坏了） | — | 删除被拒（响亮）、自动送回收站全部停手 |

## 3½. 为什么是默认关（本库规矩 ①④）

两样都是行为变更：锁会让没迁移的 app 存不了盘；记号会多一份云端文件和每次开夹多一次请求。所以都做成显式开关，默认 = 变更前的行为。各 app 打开 = 专门迁移一轮。

## 4. 和设计稿的出入（已回写设计稿）

- **`reupload` 没拦**（设计稿写的是拦）。它传的是本机已经存下的那份、内容没改，和 `resolve()` 里选「本地覆盖云端」是同一件事；拦了会把云端没了的作品卡在只有本机一份，撞第 2 条。
- **锁只管声明过的一等文档**，不是声明过的文档（图片、杂物）不拦：它们在图库里没有解锁钮，拦了就没有人的手势能放行。
- **`deleteFolder` 没加星的检查**：它本来就只删证实为空的夹，夹里有文件就拒绝。
- **记号是单独的开关 `fileMarks`**（设计稿写「star / fold 是新增动词，不受开关影响」）：建云端文件、多一次请求是行为变更，按本库规矩默认关。
- **`CloudProvider.copyItem` 没做**：留给性能和流量那一批（user 说那几件一件一件拍）。「存一版」的基本做法是读出来再写一份，不依赖它。
- 多了 `save` 的 `bornLocked`、`files.lockByDefault` / `files.fileMarks` 两个布尔、`resolve()` 的 `unresolved / starred`。

## 5. 已知的洞（写明，不藏）

- 别的设备上没更新的旧版 app、网盘自己的网页 / 文件管理器：锁和星都拦不住（user 知情）。
- 星：记号那份文件丢了 = 星没了；两台设备离线各点一次 = 逐条后改的为准；别的设备、**同一台设备的另一个标签页**还没同步到这颗星之前，在那边照样删得掉（collection 的内存信封是每页一份）。
- **清空回收站不看星**：加了星的东西如果在别的设备上被删进了回收站，这台清空回收站会把它彻底带走。要不要让清空 / 彻底删跳过加了星的 = 产品问题，等 user。
- 本机记号缓存读坏了：collection 的既有规矩是「当作空的、等云端对回来」，那一小段时间里星是看不见的（往不保护的方向坏）。没改 collection 的这条规矩。
- 锁靠本机时钟：改系统时间能让它提前或延后过期。它是保险，不是安全边界。
- 进了回收站的文件，记号条目留着不清（每条几十字节）。

## 6. 测试

- `test/lock.test.ts` 15 条：开关关着 = 旧行为；没解锁抛、字节不变不标脏云端不动；新建带解锁 / 生来锁着；放凉过期、存一次往后推；正开着的不打断、放下才落锁；改名 / 删除 / 加密不拦；补推 / 快进 / resolve 不拦；图片、二等不受影响；解锁不出现在任何云端写入里、另一台设备看不见；时钟回拨；订阅；定时器 seam（过期通知、正开着的回来看、close 收定时器）；账读坏了当作锁着。
