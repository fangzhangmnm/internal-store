# 2.2.1（patch）：谱系丢了的脏副本推之前先问云端 · 面上的 cloudState 按真相填 · pushAll 失败带原因

> created 20261026 by Claude Fable 5.1 · as-of 2.2.1 · user 2026-10-26「修，默认开」（家族根会话；起因 = user 同日「我正常编辑的时候几乎每天都在弹云冲突」）。
> 复盘与机械链：家族根 `ai-docs/20261026-cloud-conflict-ux-postmortem.md`（周账 F-98）。本文只写库这一层改了什么、为什么默认开、消费方要做什么。

## 1. 修的是什么

CatsUp（WXHW / MoonSinger 同形）正常编辑天天弹「云端有新版本」，**云端其实没人动过**。链：刷新前 30 s 内改过一笔（页面要走只落本机）→ 刷新后本地恢复先于登录 → `open()` 的云端核对没跑成，0.18.0 只给**干净**副本接谱系，脏的不碰 → 登录后快进对脏文件跳过，谱系没人补 → 之后每次推 `ifMatchFor` 算不出 If-Match → 无 If-Match 上传（`conflictBehavior:"fail"`）→ 409 → 当撞名：`pushAll` 报 failed、`save()` 弹面且 cloudState 写死 `changed`、`resolve()` 要弹两张面。

## 2. 改了什么（三件）

1. **`push.ts` `PushCfg.recaptureLineage`（默认 true）**：`doPush` 算出 If-Match 为空 ∧ 这份有 durable etag（以前同步过）→ 先 `fetchMeta`。云端 === durable → `markSeen` 重捕 parent（**和 `freshness.open` 在线时对脏副本做的是同一条规则**）→ 带 If-Match 推。云端 ≠ durable → 不再 PUT（必 412），直接走 412 那条路：`tryHeal` → 冲突面（`onConflict({ cloudState: "changed" })`）。云端没了 / 问不到 → 照旧无 If-Match 推（没了 = 建回去；问不到 = 撞了由上层 surface）。`createStore({ recaptureLineageOnPush })` 透传，默认开。
2. **`create-store.ts` `onConflictFor`**：面上的 `cloudState` 不再写死 `"changed"`。open 路径（freshness 已比过 etag ≠ base）= changed；push 刚问过云端的用带来的；其余（412 / 撞名）问一趟云端：没了 → absent / never，还是 durable 那版 → unchanged，别的 → changed，问不到 → changed。
3. **`files.dirty.pushAll()` 返回多一个 `failures: { name, reason }[]`**（`failed: string[]` 原样保留，老消费方零改动）。`reason` = `conflict`（撞真分叉，这里不弹面，去 `file.resolve()`）/ `collision`（从没同步过的新文件撞上云端同名）/ `network` / `deferred`（落地未确认）/ `error`。

## 3. 为什么默认开（库政策 ④：默认开要先写为什么不走默认关）

- 它去掉的是一个**假阳性**：If-Match 仍然是云端此刻的版本，真分叉照样 412 → 面；不新增任何「不经面就换字节」的路径，不动 keepMine / takeCloud 的派发。
- 多标签页的顾虑和 `open()` 在线时**已有**的重捕（freshness.ts「reload 后内存 _base 空…markSeen 重捕」）完全一样大，不更大——只是把同一次核对搬到推之前再做一次。
- 0.18.0 的干净那半已经默认开（user 10-21 追认），两半一开一关没法向消费方解释「为什么干净的不弹、脏的弹」。
- 默认关的代价 = 四个 app 各改一行开关之前继续天天弹假面、继续把用户引向「云端覆盖本地」丢自己最新的改动。

## 4. 行为差异（消费方升级逐条过）

| 场景 | 2.2.0 | 2.2.1 |
|---|---|---|
| 脏副本谱系丢（刷新 + 登录前恢复），云端没动 | 推 → 409 → `save()` 弹面（changed，假话）/ `pushAll` failed / `resolve()` 两张面 | 推前问云端 → 重捕 → 带 If-Match 推成功；零面 |
| 同上，云端真动过 | 推 → 409 → 面（changed） | 不 PUT，直接 `tryHeal` → 面（changed，真话）。多一次 fetchMeta、少一次必败的 PUT |
| 同上，云端没了 | 无 If-Match 推 → 建回去 | 不变（ghost 的 save 语义不在本次范围） |
| 同上，云端问不到 | 盲推 | 不变 |
| 真·新文件（没 durable etag）撞名 | mode:new 抛 collision；existing 走 surfaceCollision 面 | 不变（测试钉着） |
| 412 的面 | cloudState 恒 changed | 按真相（412 本身意味着云端动过 → 仍是 changed；撞名 409 路上可能是 unchanged / absent / never） |
| `pushAll` 返回 | `{ pushed, failed }` | `{ pushed, failed, failures }` |
| 关掉：`createStore({ recaptureLineageOnPush: false })` | — | = 2.2.0 |

## 5. 消费方义务

- 收包即生效，不用改一行。`pushAll` 的 `failures` 可用来把「N 个没传成」做成**每行名字 + 原因 + 处理…**的列表（CatsUp 2026-10-26 先做；F-88 全家跟）。
- UI 侧文案按 cloudState 四条已经是 0.18.2 的要求；现在它们终于都是真话了。
- 开机顺序「先恢复后登录」不用改——这正是本修法要兜住的；但 app 在登录落地后对**脏**文档不必再做任何补救（以前也没法做）。
