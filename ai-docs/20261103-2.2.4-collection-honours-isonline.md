# 2.2.4（patch）：collection 也吃 store 的 isOnline

> created 20261103 by Claude Fable 5.1 · as-of 2.2.4 · 家族周账 F-100（闸门）· 工单 D（小黑屋，Claude Opus 5.5）查出

## 1. 改了什么（一行）

`create-store.ts` 的 collection 工厂把 store 自己的 `isOnline`（= 宿主传的 `isOnline` ∧ `signedIn`）递给 `createCollection`。以前没递 → folder-flow 的快路径（`(!isOnline || isOnline())`）和 pull-merge-push 都当「永远在线」：宿主选了「离线继续」之后改偏好 / 阅读位置仍会 `fetchMeta` / `push`。

## 2. 行为差异

| 场景 | 2.2.3 | 2.2.4 |
|---|---|---|
| 宿主 `isOnline()` 为 false（没网 / 没登录 / 用户选了离线）时 collection 的 `reconcileWithRemote` | 照打网，失败后各自 funnel | 立即返 `{status:"offline"}`，零请求；本地照写，回线后照旧 reconcile |
| 宿主没传 `isOnline` | 看 `navigator.onLine` | 不变 |
| file 面 | 早就按 isOnline 分流 | 不变 |

不是开关：这是 2.2.2 发版说明承诺的「离线一条网都不打」对 collection 失守的 bug 修复；在线行为一字不变。

## 3. 测试

`test/collection-offline.test.ts` 两条：离线 → 零 op、offline、本地值在；在线对照 → 有 op、不报 offline。整库 539 过（2.2.3 时 537）。

## 4. 升级

消费方 `pull-package.sh 2.2.4`。接了闸门的 app（CatsUp / 小黑屋 / KudsRocket …）把 `userOffline` 接进 `createStore({ isOnline })` 后，collection 的离线行为才和 file 一致。
