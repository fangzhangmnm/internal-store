## 修掉的互等（0.18.x 都有，10-17 探针坐实）

输入：播放分片 A 在飞；pin 分片 B 已经到 `playbackIdle()` 等播放清零；此时播放也来读 B（同片去重 → 加入 pin 的 job）；然后 A 完成。期望：读 B 完成。0.18.6 的结果：读 B 持有 `playbackBusy`，pin 的 job 等 `playbackBusy == 0`，互等，**B 的 range 永远不发**（探针里 range 只打了分片 0）。
现实里什么时候会碰上：读跨两片（KudsRocket 的 256 KiB 读正好跨 2 MiB 边界）而后一片恰好是上一轮顺序预读排着的那片。以前靠「先 prefetch 再 read 的调用顺序」侥幸；接了预取库之后投机随时发，这个窗口会大很多。
修法：调度搬进 `src/chunk-scheduler.ts`，播放加入投机的 job = 升格——它在排车道 / 等让路就立刻放行（`test/chunk-scheduler.test.mjs` 第一条）。

## 镜像（替代来源）怎么设计的、怎么自愈、有什么风险

**是什么**：镜像 = 「同名同尺寸的另一份字节」的来源。两个现成实现：`createFileMirror(label, lookup)`（这台设备上的文件，File API：`<input type=file>` / `showOpenFilePicker` 拿到的 File，`slice` 白送、零网络）；`createHttpMirror(label, urlFor)`（任何支持 Range 的 HTTP 主机：局域网 / Tailscale 上的 PC）。宿主也可以自己实现 `MirrorSource`。

**身份仍归云端 item**（库对内容盲，镜像只是运输）：
1. 开会话时拿云端元信息钉版（eTag / 尺寸）照旧；然后按云端文件名 + 尺寸问每个镜像「有没有这份」（HTTP 镜像用 `Range: bytes=0-0` 探针：必须回 206 且 Content-Range 总长相等；不支持 Range 回 200 的主机当没有）。第一个健康、没被拒、有这份的排在云端前面。
2. **镜像给的第一片先和云端比过再交出去**（并发的头几片共用一次核对）。不一样 → 这份文件这一版不再用它（记在 store 实例内存里）、这路以错失败、调度器回落云端——错盘 / 重新加密过的旧容器**一个字节都不交**。
3. 之后每 16 片抽 1 片事后比。不一样 → 拒掉镜像 + 它给的**没验过的片**从 staging 里清掉（哪些片来自镜像记在 `meta.mirrored`，验过的从里面划掉）。
4. 镜像出错 / 卡住 → 这一片回落云端，镜像进冷却（30 s 起连续出错翻倍，封顶 10 min），冷却期内不打它；下一次成功清零。
5. 云端够不着而 staging 账上有这份（eTag / 尺寸已知，之前在线开过）且镜像有 → **只用镜像开会话**（`status().cloudless === true`），冷却不算（它是唯一来源）。账上没有 → 诚实抛云端的错（身份都不知道，不冒认）。

**风险（如实）**：
- R1 同尺寸、只有中段不同的文件：第一片比得过，不同处要等抽样撞到。撞到之前交出去的那些片是错的（三等资源是只读的，后果 = 宿主读到错数据，不是数据丢失；作品是另外的文件，不受影响）。抽样间隔 16 是拍的，dev 频道有数据再调。
- R2 云端够不着时的无云会话**没法核对**：身份只靠「之前在线开过 + 尺寸相等」。资源只读，最坏是宿主读不下去。
- R3 浏览器限制（宿主要知道）：HTTPS 页面只能打 HTTPS 或 `localhost`——裸 `http://100.x.x.x` 会被当混合内容拦掉，Tailscale 要走 `tailscale serve`（给 tailnet 域名发证书）；主机要回 CORS 头（`Access-Control-Allow-Origin`、`Access-Control-Expose-Headers: Content-Range, Content-Length`）并支持 Range。python 一行的静态服务器不够，宿主得配一个小脚本。
- R4 iOS 上 File 句柄活不过这次会话（WebKit 不持久化 FSA 句柄）：每次开会话要重新挑文件。桌面 Chromium 能存句柄。
- R5 隐私：镜像地址表是**设备本地**的东西（device-kv），不进云端；字节走 Tailscale（WireGuard 加密）；镜像主机是用户自配的外接服务，宿主 `CLAUDE.md` 黄线区要登记这一类（像模型镜像那条：主机只是运输，信任根是和云端比字节）。
- R6 流量：第一片核对 = 多拉一次云端那一片；对冲输了的那路已经拉到的字节是沉没成本（输了立刻中止）。计费网络下要不要关对冲是宿主的决定（`stallMs` 是开会话时定的，宿主按网络状态换值要重开会话——没做运行时改值）。

## 卡住判定为什么按「多久没到字节」

模拟器里的对冲是按请求年龄（3 s）。真机上一片 2 MiB 在 200 KB/s 的链路要 10 s，按年龄会把慢而健康的链路也对冲一遍、白白翻倍流量。按「连续 stallMs 没到一个字节」：慢的不算卡，断的才算（user 描述的「0 KB 上下、然后突然来 4 MB」正是这种）。传输层为此要按流读体报进度（`readBody`），这是 Graph range 路径唯一的改动。

## 实测状况（没有真机数据，如实）

- 48 条新测试 + 既有 450 条 = **488 全过**（3.6 s）；`tsc` 零错；api 户口刷新。
- **对冲在真机上有没有用，不知道。** 浏览器对同一主机走 HTTP/2 时多路请求复用一条 TCP 连接——如果卡的是那条连接（手机网切基站 / NAT 超时），对冲那路和原路同生共死；如果卡的是 CDN 那头的某一个请求，对冲就赢。模拟器假设的是后者。判别方法 = KudsRocket dev 频道的 `status()` / 调度器 `stats`（对冲几次、赢几次、输的那路后来到没到）；赢率接近 0 就说明是连接级，那时的正解是换来源（镜像）而不是对冲。
- 多车道的收益（9.2 vs 11.6 s）同样是模拟器数字。

## 消费方（KudsRocket）接线时要做的（宿主会话的活，不在这里）

1. `createStore({ streaming: { lanes: 3, stallMs: 3000, mirrors: () => [...] } })`；预取库那边 `budget.concurrency = lanes`。
2. 状态条接 `FileStream.status()`（W-50：`demand + speculative` 在飞、`stalled > 0` 显示「卡着」、`oldestMs` 等了多久、`mirror` 状态）。
3. 镜像：设置里一张地址表（设备本地）+ 「用这台设备上的文件」挑选；黄线区登记「用户自配镜像主机」；仓里放一个带 CORS + Range 的小服务器脚本和 `tailscale serve` 说明。
4. dev 频道采 `stats`（对冲 / 让道 / 回落次数）——决定对冲留不留。

## 版本：为什么是 2.0.0（major）

user 10-17 深夜：「bump major，其实kudsrocket的时候就该了。我现在还觉得store已经不再是原来的东西了，因为原来的身份里面只有作品，collection两种公民。现在多了save这个liminal和盘。」
- **2.0.0 不是 1.0.0**：家规「0.x 的语义就是 1.x；毕业 → 1.x 是唯一不吃书的 major；吃书 → 直接 2.x」。这里是 nature 变了（吃书），不是毕业。
- **nature 什么时候变的**：0.2.0（2026-08-20，给 Background Radio 的 SW 网关 + A1 分片会话 / staging）就长出了第二台引擎——「资源」的流式缓存；KudsRocket 0.17.x 让它承重（1.5 GB 的盘、每 20 秒一片）；本版给它调度器、镜像、状态面。所以「KudsRocket 的时候就该」是对的：从那时起这个包就是**两台引擎一个包**——① 作品的同步引擎（files + collections：If-Match、dirty、回收站、冲突面），② 资源的流式引擎（openStream / staging / 调度 / 镜像 / SW 网关）。两台共用的只有底座（provider / auth / graph 传输、IDB 分区、身份语法、错误汇报）。
- **公民等级**（SSoT = 家族根 `ai-docs/20261016-data-safety-model.md` §2 末尾那张四等表，user 10-16 的原话整理，本 README 不再另抄一份）：手动存档 / 存档罐 = **一等作品**；自动快照格 = **二等自动备份**；盘 = **三等资源**（可再得、按哈希认、可驱逐、不是任何东西的权威）；staging 账本、镜像健康表、镜像地址表 = 三等 / 四等。「save 是 liminal」说的是**写法**（程序写、高频、想先本地兜底）不是等级——它在库里仍是一个 file（dirty / push / trash / 冲突面全套），先本地后同步是 app 的 consent 政策（和画画 app 一样：自动存只落本机、推云在退出 / 换稿 / 显式按存），不需要库里长出第三种公民。
- **资源那一侧碰不碰作品**：碰不到，按构造。本版改动的文件 = `download-session` / `chunk-scheduler` / `mirror` / `range-body` / graph 的 range 读体 / `types` 第 4 个可选参数 / `create-store` 的 openStream 装配；`push` / `cloud-sync` 的写路径 / `safe-resolve` / `local-head` / `delete` / `trash` / `freshness` 一行没动。流式引擎唯一的写入 = staging 分区（只装云端拉来的字节，re-fetchable by construction）和 `adoptLocal`（本地已有副本 / dirty 一律拒绝覆盖，0.18 原样）。镜像永不写云端。不传 `streaming` 的 app 走不到新调度路径；传了的也只动资源那台引擎（user 10-17 深夜补充：「艺术类 app 不传 streaming 也许需要视频参考呢」——对，流式面是三等资源的通用面，参考窗的视频也走它；两台引擎互不 import，`test/engine-boundary-guard.test.mjs` 机械守着）。
- **SSoT 有没有被违反**：公民模型现在写在三处——MASTER §A（作品的红线）、本仓 README §0（铁律）、家族根 10-16 的四等表（最新、带 user 原话）。违反的不是数据的 SSoT 而是**文档的**：README 从没写过「资源」这台引擎的公民规则。本版的修法 = README 指向四等表，不再另写一份。
- **greenfield 长什么样（只是想，没定）**：三个包——`@internal/cloud`（provider / auth / graph / IDB 底座）、`@internal/store`（作品 + collections 的同步引擎）、`@internal/stream`（资源：openStream / staging / 调度 / 镜像 / SW 网关；`keepOffline` 是两台之间唯一的桥，今天已经是注入的 `adoptLocal` 回调）。10-15 的政策 ②（KudsRocket 专属的东西艺术类 app 永不 import）就从纪律变成物理。代价：Background Radio / RealHome / KudsRocket 要装两个包；拆的那一刀本身又是一次跨仓契约变更（= 3.0.0）。所以**这个 2.0.0 发的是现在的形状**；拆不拆、什么时候拆，另开 ADR 由 user 定。
