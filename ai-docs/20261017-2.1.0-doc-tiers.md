## 修的是哪个吃书

家族出生时假设「一个 app 一种文档」，0.16.0 的 `docKinds` 表把**身份**那层修了（后缀 / 容器 / kind），但**等级**那层没动：库对每个文件只有一套动词和后果——save 标脏 → If-Match 推 → 412 弹面 → 删进回收站 → 脏的永不驱逐。二等（自动快照格：机器可轮转、最新的赢）和三等（盘：只读、可驱逐）只能在库外用行为表达，想要「最新的赢」就只剩越狱（KudsRocket v0.1.33–35 的 presetResolution，10-16 user「禁止越狱」删掉）。这就是 06-04 风险表 H2 说的「护栏写进 doc 会被漏，要在 API 层强制」，10-16 审计写成「API 层表达不了四等表」。

## 做了什么

`DocKind` 多三个可选字段，全部在 `createStore` 时传死、冻结：

| 字段 | 意思 |
|---|---|
| `tier?: "work" \| "auto-backup" \| "resource"` | 不传 = `"work"` = 2.0 的全部行为（**零行为变化**） |
| `stem?: RegExp` | 同一后缀分几行几等：匹配主干才算这一行；带 stem 的先试（声明顺序），都不中落到不带 stem 的那行；一个后缀最多一行不带 stem；不许 g / y 旗 |
| `validate?: (plain: Blob) => boolean \| Promise<boolean>` | 这一种文档自己的采纳验真；没带用全局 `validateAdopt` |

库按等级做、也按等级**拒绝**：

| | 一等 `work`（默认） | 二等 `auto-backup` | 三等 `resource` |
|---|---|---|---|
| save 推撞 412 / 撞名（surfaceCollision） | 弹面三选一（2.0 原样） | **不弹面，这台的赢**（keepMine），输的那份**不进 .backup** | save 抛 `ReadOnlyFilesError` |
| open 时本地脏 ∧ 云端变了 | 弹面 | 不弹面，留这台的（之后推 → 上一行） | 不会脏 |
| `resolve()` | 弹面 | 不弹面：脏 → 这台的赢；干净 ∧ 云端没了 → 跟着云端（本地那份进回收站，别的设备轮转掉的格子不该被这台复活） | 恒 `clean` |
| `open()` 本地没有 | 按 `autoCacheOpenedFile` | 同一等 | **一律过路**不留本地（读走 `openStream` / `keepOffline`） |
| `tryMove / delete / reupload / encrypt / decrypt / rekey` | 照常 | 照常（删进回收站） | 全抛 `ReadOnlyFilesError`（消息「三等资源「…」只读：op」） |
| 云端没了（reconcile cloud-gone） | 宽限后本地进回收站 | 同一等 | **本地缓存直接丢**（`local.hardDelete`，不进回收站） |
| 脏的不驱逐 / 离线补推 / 两 tab 互覆护栏 | 照常 | 照常 | 不会脏 |
| 永不被机器提升成一等 | — | 库里没有「提升」这个动词；人「读这一份」再手动存 = 人做 | — |

实现：`identifiers.ts`（表 / parse 带 `tier` / 新 `rowOf`）、`create-store.ts`（`tierOf` / `tierGuard` / 三处 push 的 `loserBackup` / 三处面的分流 / open 过路 / reconcile `drop`）、`safe-resolve.ts` + `cloud-sync.ts`（`weakOverride` 可不备份；`validateAdopt(plain, name)`）、`push.ts`（`loserBackup` 透传）、`reconcile.ts`（`drop` 谓词）。不是文档的名字（表里没有的后缀）按作品处理 = 2.0。

## 行为差异（和 2.0.0 比）

- 不传 `tier` 的消费方：**零差异**（497 条旧测试原样过；`DocIdentifier` 多一个 `tier: "work"` 字段）。
- 新导出：`DocTier` 类型；`Identifiers.rowOf`；`ReadOnlyFilesError` 构造多一个可选参数。`CloudSync.weakOverride` / `SafeResolve.resolveConflict` / `PushOpts` 多可选的 `backup` / `loserBackup`（库内）。
- 定了（user 同夜）：二等的**轮转**（`keep: N`、按什么序）归 app——「同意，我们不应该管太多」；二等的 `delete()` **也进回收站**，和一等一致——「我权衡了一下，delete语义一致比较好」（库里没有按等级分叉的删除）。`Item` 列举面不带 `tier`：和 `kind` 一样，列举行只带身份和同步事实，等级 / 种类都从 `store.identifiers.parse(identifier)` 推——gallery 画徽章就调它，不另复制一份。

## 风险

- `stem` 是正则：写错 = 文件落错等级。自动格被当成一等只是多弹面（安全侧）；**手动格被当成二等 = 真分叉时这台静默覆盖云端、输家不留底**。所以 stem 要窄（KudsRocket 的 `-[ah]\d+$` 只认 `-a<数字>` / `-h<数字>`），宿主要有一条守卫测试把自己的表跑一遍（手动 / 自动 / 历史各一例）。
- 二等「这台的赢」靠的是「人在这台」，不是时钟：两台同时自动存同一格，后推的赢。表里允许（「机器可以最新的赢」）。
- 三等 `open()` 过路 = 整份进内存不落盘（和 `autoCacheOpenedFile:false` 一样）；大资源该走 `openStream`，这条只是兜底。

## 消费方要做的

KudsRocket：`docKinds` 五行改成上面 README 的形状（三种大文件后缀 → `tier: "resource"`；`.crumb` 加一行 `stem: /-[ah]\d+$/, tier: "auto-backup"`；`.jam` 留一等）；删掉 app 侧为自动格绕路的代码（如果还有）；加一条表的守卫测试。艺术类 app：不传 tier，升级零差异；要用参考视频时 `.mp4` 一行 `tier: "resource"`。
