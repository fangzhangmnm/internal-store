# 2.1.3：镜像抽样核对在并发下真的会抽（节拍在片到达那一刻定）

> created 20261021 by Claude Fable 5.1 · as-of 2.1.3 · 周账 F-61 / F-63 审计（道 1 库）查出，patch。

## 问题（输入 / 输出）

- **输入**：`streaming.mirrors` 开着，`lanes ≥ 2`（KudsRocket 是 3），镜像给的片并发到达。
- **应该**：镜像交出的第 1 片先和云端比过再交（没变）；之后**每 16 片抽 1 片**事后比，不一样就拒掉镜像、清它没验过的片（2.0.0 发版说明 §镜像）。
- **实际**（2.0.0–2.1.2）：`arrived()` 先 `mirrorChunks++`、再 `await` 落 staging、**之后**才看 `mirrorChunks % 16`。三路并发时第 16 片醒来一看计数已经是 17、18 → 不抽；第 17、18 片同理。顺序读（一次一片）才抽得到。KudsRocket 真机就是三路并发 + 预取库在后面投机——**抽样几乎从来没发生过**，R1 的残余风险比发版说明写的大。

回归测试：`test/download-session.test.mjs`「镜像抽样核对在并发下也按节拍抽」——镜像只有第 1 片和云端一样、一口气要全盘 20 片（3 路）→ 旧码 `status().mirror` 还是 `ok`，新码 `rejected`。

## 修法

`arrived()` 在片到达那一刻记下「这是镜像交出的第几片」（`seq`），传给 `sampleVerify(i, bytes, seq)`；抽不抽看 `seq % 16`，不再看之后的计数。一行语义：**节拍按到达顺序定，和落 staging 的先后无关**。

## 行为差异

- 开镜像且并发读的宿主：抽样核对现在真的每 16 片一次（多一次云端 range）。没开镜像：零变化。
- 没改的：第 1 片必比；拒掉后清未验片；冷却；无云会话只用镜像。
- 残余风险 R1 原样成立（抽样撞不到的中段差异仍会交出去）。**盘的正解仍是 KudsRocket W-44「明文分片哈希表进 KRD2 头」**：审计顺带核过，KRD 正文是 AES-256-CTR、**逐片没有认证**（`src/disc/crypt.ts`），加密盘和明文盘一样只能靠抽样——所以 W-44 值得做，归 KudsRocket 那条道。
