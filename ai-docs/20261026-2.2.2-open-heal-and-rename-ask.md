> 起因：MoonSinger 开歌前无条件 `pushDirtyAll` 一遍，为的是借推路径的字节比对自愈躲开 open 的假面（10-08）；周账 F-92 改名多出一份 = 库降级另存 + UI 吞旗（家族根复盘 §8）。

## 1. 改了什么

1. **`freshness.open`**：脏 ∧ 云端版本号 ≠ 基准 → 弹面之前先试自愈：meta 里的大小 ≠ 本机大小 → 不可能一样、不拉（守住「面前不预拉整份云端」）；一样 → 拉云端逐字节比（`safeResolve.tryHeal`，和推路径同一条规则），相等 = 上次推其实落了、回执没回来 → `markSynced`、不弹面、脏标清；不等 → 照旧交 `onNewer`。**拉的过程和「跳过到离线」的 probe 赛跑**：probe 先到 → 当 skipped（读本机、不弹面、谱系不动；迟到的比对若相等仍 markSynced = 关于字节的事实，无害）。`OpenOpts.localBytes` 由 createStore 注入。
2. **`identity.rename`**：在线 ∧ 这台有没传的改动 ∧ 云端确实有旧名 ∧（基准不明 ∨ 基准 ≠ 云端版本号）→ **动任何字节之前**问 `ui.resolveRenameOld({ oldName, newName, reason: "diverged" | "unknown-lineage" })`：`trash` = 新名推上去后把云端旧名移进回收站（可恢复，永不硬删）；`keep` = 留着（两份，`tryMove` 返 `oldKeptByUser`）；`cancel` = 不改名、一个字节不动（`tryMove` 返 `{ ok: false, reason: "cancelled" }`）。宿主没给回调 = 2.2.1 行为（默认留着 + `oldKept`）。谱系明确（干净 / 脏但云端没动）照旧不问。
3. 类型：`StoreUI.resolveRenameOld?`、`TryMoveResult` 多 `oldKeptByUser` 和 `{ ok: false; reason: "cancelled" }`、`IdResult.oldKeptByUser`。

## 2. 为什么不是开关 / 为什么默认有

- 自愈那条：不是行为变更开关，是把推路径已有的「字节一样就认领」补到 open 路；它只去掉假阳性（字节不等照样弹面），不新增任何覆盖路径；大小闸让「面前双倍下载」只在大小相同（= 多半真是同一份）时发生。和 2.2.1 同一理由。
- 问人那条：**宿主接了回调才生效**（= 消费方显式开），没接 = 旧行为。按钮词「搬走旧的（进回收站）/ 留着旧的 / 取消」= user 10-26 批的词汇表扩一格，「不删就行了」= 搬走只进回收站。
