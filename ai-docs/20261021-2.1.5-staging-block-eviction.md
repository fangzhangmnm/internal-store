# 2.1.5：流式暂存区按块淘汰 + 钉热集（streaming 模式）

> created 20261021 by Claude Fable 5.1 · as-of 2.1.5 · user 2026-10-21「store 的其他做」；出处 = 预取库出生稿「还没做 / 归谁：store（交 Fable，要 user 批）……按块的淘汰 + 钉热集」、KudsRocket W-20。patch（只在 `streaming` 显式开关的伞下生效；0.18 模式零变化）。

## 以前

staging 超过 `capBytes`（默认 256 MiB）→ 按**整组**（整个文件）FIFO 清最久没碰的，**在用会话一个字节不动**。KudsRocket 一张盘 1–2 GB、一局就是那一张 → 在用会话越长越大、上限形同虚设；不在用的盘又是整组清，下次开盘什么都不剩。

## 现在（`streaming` 模式）

- **按块**：候选 = 账上所有块，**除了**在用会话里 `hotMs`（默认 60 s）以内碰过的（钉热集：正在玩的那一段、预取库刚投机拉来的）。
- **顺序**：不在用的会话先于在用的 → 命中次数少的先（一次性顺序扫过的块 hits = 0，比反复用到的块先走 = 抗扫描污染，S3-FIFO 的那层意思）→ 最久没碰的先。
- **记账**：`StagingMeta` 多两项（`hot` / `hits`，键 = 块号）：到账 = 热、0 命中；从 staging 命中 = 热、命中 +1（封顶 8）。命中只改内存账、最多每 2 s 落一次盘；关会话落一次。老账没有这两项 = 当冷块、0 命中（零迁移）。SW 网关共用同一 schema，多两个可选键它不看。
- **在用会话的内存账同步**：淘汰了它的块 → `got` / `mirrored` / `verified` 一起划掉（coverage 立刻对、再读从云端重拉，不会误以为还在）。
- **不每片都扫全表**：占用估计在内存里（到账 +、淘汰 −），估计没超限不扫 `keys()`；`purgeName` 让估计作废、下次重算。
- 整组都走了 → 账也删；在用会话的账留着（空）。

## 0.18 模式（不传 `streaming`）

照旧：整组 FIFO、在用会话不动。JRB / Background Radio 的流播零变化。

## 没做

- 真 S3-FIFO 的三条队列（小 / 主 / 幽灵）没抄全，只取了「新来的一次性块先走」这层；真机数据（KudsRocket dev 黑匣子）出来再看要不要。
- `hotMs` 只有构造参数，没有运行时改。
