# 2.3.5（patch）：网络报错里不再有上游报错的原文——只剩固定字样、主机名 / 文件名 / 用时、固定词表的类别

> created 20261112 · 规矩 = 统筹 Claude Fable 5.2（小黑屋维修线重审裁定一，推翻 2.3.3 的「找地址再删」）· 代码 / 测试 Claude Opus 5.5（小黑屋维修线小弟）· as-of 2.3.5（**没打 tag、没出 tgz，等统筹审**）
> 2.3.5 = 2.3.4（按请求种类分超时档，tag 也还没打）+ 本篇。

## 1. 毛病

2.3.3 让下载报错只带主机名，做法是「在原错的字里找 `scheme://…` 整段换成主机名」（`scrubUrls`），cause 字里带地址就换一份洗过的（`safeCause`）。统筹重审时写了攻击脚本：14 种带假签名的地址写法里漏 9 种——路径里带括号或撇号、查询串里带引号或尖括号、地址没有协议头、换行、错误里再套一层错误、错误对象上另挂地址字段、抛的不是 Error。「在别人给的一段话里找地址再删」挡不住没见过的写法。

## 2. 改了什么

1. **上游报错的原文一个字都不进我们的报错**（`src/base/providers/graph.ts`）。网络报错的字只由三样拼成：
   - 我们自己的固定字样（`downloadUrl: network fetch failed`、`range download: body failed`、`content via Graph: …`、`Graph upload session status: …`、`Graph copy monitor: …`）；
   - where 那一串：`host=<主机名> file="<文件名>" after=<毫秒>ms`；
   - 一个固定词表里的类别（`src/base/errors.ts netCategory`）：`failed-to-fetch` / `load-failed` / `network-error` / `fetch-failed` / `aborted` / `timed-out` / `other`。按原错的 `name`（TimeoutError / AbortError）和四句已知原话精确相等归类（Chromium「Failed to fetch」、WebKit「Load failed」、Firefox「NetworkError when attempting to fetch resource.」、Node「fetch failed」）；对不上就是 `other`，不抄任何一段。
2. **cause 不再挂原错对象**，挂一个冻结的替身 `{ name, category }`（`netCause`）：`name` 也走固定词表（TypeError / AbortError / TimeoutError / NetworkError / DOMException / Error，其余 = `other`），没有 message、没有 stack、没有别的字段。
3. **graphFetch 的路径**：我们自己拼的相对路径原样；整条绝对地址（分页的 nextLink）只留主机名。按「能不能单独解析成地址」判（`new URL(p)`），不用正则去找。非 2xx 的那一句也一样。
4. 分块上传接着传时的原因串（`resumeFrom` 的 why）同样只放类别。
5. `scrubUrls`、`safeCause` 删掉。

## 3. 行为差异

| 场景 | 2.3.3 / 2.3.4 | 2.3.5 |
|---|---|---|
| 下载被拦（Chromium） | `… after=12ms (TypeError: Failed to fetch)` | `… after=12ms (failed-to-fetch)` |
| 原错的字带着地址或别的东西 | 洗过的原文 | `(other)` |
| `err.cause` | 原错对象（或洗过的同名一份） | 冻结的 `{ name, category }` |
| nextLink 那一趟断了 | `Graph GET <洗过的地址>: …` | `Graph GET graph.microsoft.com: …` |
| 没开 timeouts、别的一切 | — | 不变（stage / host 字段、重试语义、status 都不变） |

**cause 的契约变了**：以前 `test/graph-network-error.test.ts` 钉的是「原始 TypeError 保留在 cause（诊断可追）」，现在钉替身。查过谁读 cause：库里没有（`stream/mirror.ts` 只造不读）；小黑屋、MoonSinger 没有；CatsUp 读的是它自己的 `OpApplyError.cause`，和库无关。三个宿主也都不按报错的字面做判断。

## 3½. 为什么默认开（本库规矩 ④）

这是安全的硬规矩（下载地址带签名，拿到就能下载），做成开关 = 允许关着泄地址。宿主拿到的 stage / host 字段和重试语义都没变，变的只是字里少了上游原文、cause 换成替身。

## 4. 测试

- `test/graph-download-diagnostics.test.ts`：统筹攻击脚本的 **14 种写法 × 六条路**（整份下载 / 按范围下载 / `/content` 兜底（被跳到签名地址上断）/ 上传会话分块 PUT 断 / 上传会话接着传时问进度也断 / 复制监控），每一条查 message、String、stack、整条 cause 链、JSON 序列化（含自有属性），一个签名片段都不许有，cause 只有 name 和 category；nextLink 只留主机名、相对路径原样；浏览器原话精确对上才归类、替身冻结。**结构守卫**：graph.ts 构造网络报错的那几行不许出现 `String(e)` / `e.message` / `e.stack`，cause 不许直接挂原错，报错模板里不许插地址变量，`scrubUrls` / `safeCause` 不许回来。
- 反证：把整份下载那一处的类别换回 `String(e)` → 4 条红。
- 统筹的攻击脚本（`scrub-attack.ts`）对 2.3.5 跑：14 种 × 两条下载路 no leaks。
- 全套 641 条全绿；对外接口（`api/*.api.md`）无变化。

## 5. 还带着上游原文的两处（统筹审稿裁定）

1. `graphFetch` 非 2xx 那一句末尾的 `detail` = Graph 回的错误正文（JSON：code / message / innerError）。**保留**（诊断要用），**截到 300 个字符**（`GRAPH_DETAIL_MAX`；报错的字和 `err.body` 都截，多出来的换成「…」）。查过：库和三个宿主都不读 `err.body`。测试 +1。
2. 资源引擎 `src/stream/mirror.ts` 的镜像下载失败把 `String(e)` 拼进字里、cause 挂原错。**这次不动**：镜像地址是用户自己配的局域网 / Tailscale 主机，不是带签名的临时地址。

## 6. 谁收

只有小黑屋收（它现在钉的是本地出的 2.3.4 包）；统筹审过再打 tag（2.3.4 和 2.3.5 都还没打）。MoonSinger、CatsUp 不碰，它们开着同样的超时设置、有 2.3.4 修的那个口子，等各自收。
